# Readable

A name is **readable** when someone who has never seen the project knows what is inside from the name alone, at a glance.

## Steps

1. **Collect** every name in play: the ones you are about to create, and the ones that arrived (uploads, downloads, unpacked archives, extracted output, tool defaults).
2. **Learn what each one is** from its contents (open it, list it, read its first lines), never from the name it came with or the place it came from. Names inherited from an archive, a sender or a tool say who carried the thing, not what it is.
3. **Write the name** as a short phrase for the thing's role: what it is, in the words the project already uses (`haim-recitations-slides`, `exam-solutions`, `slides-deadlocks`). Match the language, casing and separators of its siblings.
4. **Check each name** against the test: a stranger reads it and states the contents correctly. Placeholders (`Presentation3`, `new folder`, `final2`, `file (1)`, `misc`, `data`, `untitled`) and container words (`unpacked`, `output`, `files`) fail it.
5. **Ask** when step 2 leaves the meaning open, when two readings are plausible, or when the thing is the user's own original: put one proposed name next to the question, and let the user pick.
6. **Rename** generated and derived names yourself. Rename the user's originals only after they agree.
7. **Close the loop**: search the project for the old name (docs, scripts, commands, config, handoff pages) and update every hit.

## Done when

- Every name you touched passes the stranger test.
- No reference to a replaced name remains anywhere in the project.
- Every doubtful name was put to the user, and nothing was renamed on a guess.
